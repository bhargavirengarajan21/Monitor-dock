🧠 Incident Memory

AI that remembers how your team fixed things — so the next person doesn't spend an hour rediscovering yesterday's fix.

The problem

During an incident the real fix is worked out on a call. When the call ends, that knowledge disappears — nobody has time to write it down.
  • ✕ "Chat with your docs" misses exact error codes like ERR_PAYMENT_409 — vectors match meaning, not strings.
  • ✕ It quotes stale runbooks for services that have changed.
  • ✕ It can leak answers across teams that shouldn't see them.
  • ✕ It invents an answer when nothing relevant exists.

The solution — two paths

① Capture

An incident call is transcribed, Muse Spark drafts a structured postmortem (cause, fix, owner, deploy), and an engineer approves it with one click. Only approved postmortems become memory.

② Recall

When the same alert fires again, Incident Memory finds the past incident, checks live errors and recent deploys, and answers in seconds with the fix and citations — or says "No similar incident found".

A human approves every postmortem, so an AI mistake never becomes team knowledge.

How recall works — 5 steps

  • 1Alert arrives — a New Relic or Prometheus webhook, normalized into one format.
  • 2Permission filter — restrict to the team's documents before retrieval.
  • 3Hybrid search — keyword (exact codes) + vector (meaning), merged with reciprocal rank fusion.
  • 4Score check — below threshold → "No similar incident found", no guessing.
  • 5Cited answer — Muse Spark writes the fix, every claim linked to a source.

Architecture

Alert webhook→ Permission filter→ Hybrid search→ Threshold→ Cited answer
Approve postmortem→ Kafka: postmortem.approved→ Indexer: chunk · embed · tag team→ Postgres + pgvector
Every monitoring tool plugs in through one connector contract — add a tool without touching recall or capture.
